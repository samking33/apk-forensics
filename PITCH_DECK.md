## Slide 2: The Problem: The Limits of Automation
**Headline:** Why Traditional Scanners Fall Short
- **Automated Blind Spots:** Traditional tools like MobSF rely on static signatures, regex, and predefined rules. They struggle with:
    - Obfuscated code logic.
    - Complex business logic vulnerabilities.
    - Context-aware malware (e.g., checks for emulators).
- **Noise & False Positives:** Automated scanners often flood analysts with irrelevant warnings ("High Risk: Logs Found") without understanding the *intent* of the code.
- **The "Human" Gap:** Malware analysis requires intuition and reasoning. Scripts can find *what* is there, but they rarely understand *why* it is there.

---

## Slide 3: The Solution: fSOC APK Forensics
**Headline:** AI-Augmented "Manual" Forensics
- **Concept:** A CLI tool that orchestrates Claude AI to act as a **Senior Mobile Malware Analyst**.
- **Approach:** Instead of just scanning, we *investigate*.
    - Decompiles APKs using industry-standard tools (`apktool`, `jadx`).
    - Feeds raw code and context to a state-of-the-art LLM (Claude 3.5 Sonnet).
    - Performs deep, semantic analysis of the code structure and intent.
- **Result:** High-fidelity forensic reports that read like they were written by a human expert, not a machine.

## Slide 6: How It Works
**Headline:** The Intelligence Pipeline
1.  **Ingest:** User provides an APK file.
2.  **Deconstruct:** Tool automates `apktool` and `jadx` to expose source code and resources.
3.  **Analyze:** The "Senior Analyst" persona (Claude AI) reviews the manifest, permissions, and decompiled code.
4.  **Reason:** The AI traces logic paths (e.g., "Is this permission used for legitimate functionality or data theft?").
5.  **Report:** Generates a comprehensive text-based report with findings, IoCs, and remediation steps.
